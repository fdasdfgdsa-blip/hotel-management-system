## ADR-002. Взаимодействие через контракты

**Статус:** Принято.

**Проблема:** Прямое обращение одного модуля к внутренним классам
другого увеличивает связанность приложения.

**Решение:** Взаимодействие модулей выполнять через публичные
интерфейсы и DTO.

Например:

```
BookingModule
        ↓
IRoomReservationService
        ↓
RoomModule
```

**Последствия.**

Положительные:

- модули слабее связаны;
- проще выполнять тестирование;
- контракт взаимодействия можно изменить контролируемо.

Отрицательные:

- необходимо поддерживать дополнительные DTO и интерфейсы.
