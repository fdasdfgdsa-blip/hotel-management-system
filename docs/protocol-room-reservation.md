# 11. Протокол взаимодействия № 1
## Резервирование номера

## 11.1. Инициатор и получатель

Инициатор: `BookingModule`
Получатель: `RoomModule`

## 11.2. Назначение

Протокол используется при создании бронирования.
Перед сохранением бронирования необходимо убедиться, что выбранный
номер свободен на необходимый период, и зарезервировать его.

## 11.3. Механизм вызова

Асинхронный вызов через интерфейс C#: `IRoomReservationService`.
Зависимость передаётся через механизм Dependency Injection.

## 11.4. Точка входа

```csharp
Task<ReserveRoomResult> ReserveAsync(
    ReserveRoomRequest request,
    CancellationToken cancellationToken);
```

## 11.5. Формат запроса

```json
{
  "roomId": "a1b2c3d4-1234-5678-abcd-ef1234567890",
  "bookingId": "f9e8d7c6-4321-8765-dcba-fe0987654321",
  "checkInDate": "2026-10-01",
  "checkOutDate": "2026-10-05"
}
```

## 11.6. Успешный ответ

```json
{
  "success": true,
  "errorCode": null
}
```

## 11.7. Ошибки

Возможные ошибки:

| Код | Описание |
|-----|----------|
| ROOM_NOT_FOUND | Номер не существует |
| ROOM_NOT_AVAILABLE | Номер занят на выбранный период |
| INVALID_BOOKING_PERIOD | Некорректный период проживания: дата выселения раньше даты заселения или совпадает с ней |

Пример:

```json
{
  "success": false,
  "errorCode": "ROOM_NOT_AVAILABLE"
}
```

## 11.8. Таймаут

Операция должна завершиться не более чем за 3 секунды.
При отмене запроса используется `CancellationToken`.

В текущей реализации резервирование выполняется в памяти и
завершается сразу, отдельное ограничение времени не задаётся.

## 11.9. Повторная отправка

Автоматический повтор операции резервирования не выполняется.
Причина: повторный вызов без дополнительной проверки может привести
к неоднозначному состоянию резерва.
Повтор операции выполняется только после проверки результата
предыдущего вызова.

## 11.10. Аутентификация

Дополнительная аутентификация между модулями не выполняется,
поскольку они работают внутри одного серверного приложения.
Проверка прав пользователя выполняется на уровне API.

В текущей версии API аутентификация не реализована.

## 11.11. Версия контракта

`RoomReservationContract v1`

## 11.12. Пример обмена

```
BookingModule
       │
       │ ReserveAsync(...)
       ▼
 RoomModule
       │
       │ Проверка периода
       │ Проверка номера
       │ Проверка свободных дат
       │ Создание резерва
       ▼
 ReserveRoomResult
       │
       ▼
 BookingModule
```

Перед вызовом `ReserveAsync` модуль `BookingModule` получает номер
через `IRoomCatalogService`, поэтому для несуществующего номера
клиент получает `ROOM_NOT_FOUND` до проверки периода.

При успешном резервировании `BookingModule` продолжает создание
бронирования. При ошибке `ROOM_NOT_AVAILABLE` бронирование не создаётся.
